# 📄 CONCLUSIONES

- 📌 Unidad 1:

Esta unidad sirvió para entender cómo se planifica un programa antes de escribir código real. El uso de pseudocódigo y las pruebas de escritorio fueron esenciales para detectar errores a tiempo y aprender a pensar de manera lógica, facilitando el salto de la programación por bloques a un lenguaje de programación formal.

- 📌 Unidad 2:

Aquí el enfoque cambió hacia la toma de decisiones y la automatización. Gracias a las estructuras condicionales y repetitivas, los programas dejaron de ser lineales para poder adaptarse a diferentes situaciones y repetir tareas de forma automática, lo que permitió resolver problemas mucho más dinámicos.

- 📌 Unidad 3:

Esta última etapa permitió organizar mejor los datos y el código. Con los arreglos, fue posible manejar grupos de información bajo una misma estructura, mientras que la programación por módulos ayudó a dividir problemas grandes en partes más pequeñas y manejables. El aprendizaje sobre el paso de parámetros por valor y por referencia fue clave para entender cómo los datos interactúan realmente dentro de un programa.
